# Review of P0 to P2, 2026-09-21

An independent review of the tree at `d8dffeb` (turbo-v2), reproducing every
finding it could in a scratch crate. This file tracks each item to closure.
Items are closed only by a commit that carries a test for the failure.

## Critical

| Id | Finding | Status |
|----|---------|--------|
| C1 | `plugin_export::x_session_run` handed out `Arc::as_ptr(buffer)` as a buffer handle while `buf()` reads handles as `*const Arc<dyn ProviderBuffer>`; `turbo_result_read`/`turbo_buffer_export` on a plugin result dereferenced garbage (segfault reproduced against the mock plugin). | Fixed: output handles are boxed `Arc`s with stable addresses, the same representation as allocated buffers. Covered by the CUDA live tests, which read device results through the plugin path. |
| C2 | The result lease (`AtomicBool`) was checked before taking the session mutex, so a write or second run could proceed while a result was held. | Fixed: the lease is checked under the session lock. |
| C3 | `check_size` accepted any size in `[4, sizeof]`, including sizes ending inside a pointer; `turbo_generation_create` with `struct_size = 68` dereferenced half of `stop` (segfault reproduced). | Fixed: `turbo_abi::Versioned` lists every field end per struct (generated by `scripts/gen-versioned.py`); only those sizes are accepted. Test: `contract_struct_size_inside_a_field_is_rejected`. |

## High

| Id | Finding | Status |
|----|---------|--------|
| H1 | `turbo_buffer_export` wrote 24 bytes past a caller's smaller `struct_size`. | Fixed: bounded `write_sized`. |
| H2 | `turbo_buffer_desc.next` was read as a full `turbo_native_handle` regardless of its `struct_size`. | Fixed: read through `read_sized`. |
| H3 | OpenVINO `x_session_run` and `x_buffer_alloc` copy a result whose `struct_size` is the provider's, overwriting the caller's declared size. | Fixed: both go through `write_sized`, which keeps the caller's declared size and copies only that many bytes. Tests: `providers/openvino/tests/provider_test.cpp` `buffer_alloc_keeps_the_callers_struct_size`, `session_run_keeps_the_callers_struct_size`. |
| H4 | OpenVINO token-classification row assembly admits a word that straddles the token budget with its full sub-token count (`first_token + n_tokens > seq`), and left truncation skips whole words against a token-granular `skip`. | Fixed: `Session::collect_words` places each word at the column it actually occupies (`1 + n_prefix + (seen - skip)`) and drops any word truncation cut in half, on either end, so `first_token + n_tokens` always stays inside the row's live tokens; `aggregate_spans` re-checks that bound and fails with `TURBO_E_INTERNAL` rather than reading on. Tests: `providers/openvino/tests/provider_test.cpp` `left_truncation_maps_words_to_their_columns`, `right_truncation_drops_the_word_that_straddles_the_budget` (both read past the row on the previous build). |
| H5 | Bundle verification does not hash `bundle.json`, and `resolve()` follows symlinks out of the bundle directory. | Fixed: `Bundle::manifest_sha256()` is the hash of the manifest bytes (the bundle's identity, to be pinned like artifact hashes); `resolve()` canonicalizes and rejects paths outside the bundle. Tests: `bundle_integrity_rust.rs`. |
| H6 | Importer drops Dense projection modules, takes `max_seq` from `max_position_embeddings`, never cross-checks `1_Pooling` `embedding_dimension`, and hardcodes classifier activations. | Fixed: any module other than Transformer + Pooling [+ Normalize] is refused, a second Pooling is refused, `max_seq` comes only from `sentence_bert_config.json`, `tokenizer_config.json` `model_max_length`, or `--max-seq` (else refused), `hidden_size` must equal the pooling config's `word_embedding_dimension`, and activations follow `problem_type` / `sbert_ce_default_activation_function`. Tests: `tools/turbo-bundle/src/import.rs` `refusals`. |
| H7 | Options advertised but clamped or ignored: mock `max_tokens` clamped to the session; `prompt_role` accepted on prefix-less bundles; mock LEFT truncation drops the prefix; OpenVINO `TRUNCATE_RIGHT` on pairs falls to longest-first; OpenVINO CPU advertises `HOST_PTR_IMPORT` with a NULL import slot. | Core and mock parts fixed: the core refuses `max_tokens` above the session width (`TURBO_E_CAPACITY`, field 3) for every provider, refuses a prompt role the bundle has no prefix for (`TURBO_E_INVALID_ARGUMENT`, field 4), and the mock keeps the prefix under LEFT truncation. Tests: `honesty_rust.rs`. OpenVINO parts fixed: `write_pairs` maps MODEL to longest-first, RIGHT to query-priority (the query is kept whole and the document is truncated), NONE to the packer's error policy, and refuses LEFT with `TURBO_E_UNSUPPORTED_OPTION` field 2; host-pointer import is implemented (the pointer is wrapped, never copied, and the caller keeps ownership) for every device that advertises the bit. Tests: `live_tasks.rs` `live_rerank_right_truncation_keeps_the_query_whole`, `live_embed.rs` `live_host_pointer_import_follows_the_capability_bit`, `providers/openvino/tests/provider_test.cpp` `host_pointer_import_aliases_caller_memory`. |

## Medium

- Generation options without a capability bit or gate (`temperature`, `top_k`,
  `top_p`, `min_p`, `min_new_tokens`, `echo`, `stop_tokens`, `raw_scores`).
  Fixed: `TURBO_CAP_OPT_GEN_SAMPLING`, `TURBO_CAP_OPT_GEN_MIN_TOKENS`,
  `TURBO_CAP_OPT_GEN_ECHO`, `TURBO_CAP_OPT_GEN_STOP_TOKENS`, and
  `TURBO_CAP_OPT_RAW_SCORES` gate them with the field index; the mock models
  sampling deterministically (seed-dependent draws, `top_k`/`top_p`/`min_p`
  shrink the pool) and greedy decoding ignores the seed. Tests:
  `honesty_rust.rs`.
- `return_sorted` gated by the `TOP_N` bit and reported as field 4; it is
  field 5. Fixed (field 5).
- Output dtype gate hardcodes F32 rather than comparing with `dtype_used`.
  Fixed: only a dtype equal to `dtype_used` is free.
- `validate_contract` checks presence, not parseability; no
  `deny_unknown_fields`; `source_sha256` absent from `Manifest`. Fixed:
  every enumerated contract value must parse, manifests reject unknown
  fields, scored models must declare `activation`, token classifiers
  `aggregation`. `source_sha256` is superseded by `manifest_sha256`.
  Tests: `bundle_integrity_rust.rs`.
- `contract.activation` unused by the mock provider. Fixed: the mock applies
  the declared activation (softmax, sigmoid, none) to rerank and classify
  scores.
- `TURBO_STAGE_*` names both stage indices and placements; `TURBO_CAP_*`
  names both statuses and bits. Naming collision in the header. Open.
- `turbo_span` and `turbo_chunk` have no `struct_size`. Open.
- `plugin.rs` trusts `n_outputs`/`n_spans` from a provider without a bound.
  Fixed: `MAX_PLUGIN_OUTPUTS` (256) and `MAX_PLUGIN_SPANS` (2^24); more is
  `TURBO_E_INTERNAL`.
- OpenVINO `top_n` not clamped to `n_rows` (unreachable through the core,
  which rejects `top_n > rows` with `TURBO_E_INVALID_ARGUMENT` field 4; still
  due in the provider). Fixed: the sorted output is clamped to the rows that
  were written, so no index the sort never touched is published. Test:
  `providers/openvino/tests/provider_test.cpp`
  `rerank_options_are_checked_and_top_n_is_clamped`.
- OpenVINO maps unknown `truncate`, `aggregation`, `prompt_role` values to
  defaults instead of `TURBO_E_INVALID_ENUM`; `AGGREGATE_FIRST` and `SIMPLE`
  are indistinguishable; span score is the minimum rather than the mean.
  Fixed: `checked_truncate` / `checked_prompt_role` / `checked_aggregation`
  refuse an unrecognized value with `TURBO_E_INVALID_ENUM` and the field
  index, a bundle `contract.aggregation` that names no strategy is
  `TURBO_E_BUNDLE_INVALID` at load, and a group's score is the mean of its
  word scores, as in the CUDA provider. `FIRST` and `SIMPLE` still agree by
  construction: spans here are word-aligned, which `aggregate_spans` now
  documents. Tests: `providers/openvino/tests/provider_test.cpp`
  `unknown_embed_enums_are_invalid_enum`,
  `unknown_classify_enums_are_invalid_enum`,
  `rerank_options_are_checked_and_top_n_is_clamped`,
  `span_score_is_the_mean_of_the_word_scores`.

## Low

`turbo_error.struct_size` unchecked; `&mut *out` over a possibly shorter
caller struct; unused status codes; `header_parity.rs` checks sizes only;
`turbo_types.h` lacks `extern "C"`; `tokenizer_sha256` falls back to the
first file. All open.

Fixed: the OpenVINO CPU device reports the vendor read from the CPU
(`GenuineIntel` / `AuthenticAMD`, else 0 and `unknown`) and a GPU reports its
OpenCL vendor, instead of Intel for every device; the four release entry
points delete through a `noexcept` helper, so a throwing `clRelease` during
teardown cannot unwind out of a `void` vtable slot and terminate the caller.
Test: `providers/openvino/tests/provider_test.cpp`
`cpu_device_reports_the_host_cpu_vendor` (the machine it was run on is an AMD
Ryzen 9 9950X3D, which the previous build called Intel `0x8086`).
