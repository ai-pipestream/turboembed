# The generated Snowball stemmers

`src/snowball/algorithms/*.rs` are generated by the Snowball compiler from the
Snowball sources (`algorithms/<language>.sbl`) at commit
`9a22f0d3f44cda36677829328fe2642750114d57` of
https://github.com/snowballstem/snowball (January 2025, after release 2.2.0
and before 3.0.0; the compiler still calls itself 2.2.0). OpenNLP's Java
classes in `opennlp.tools.stemmer.snowball` name that commit in their headers,
and the compiler's Java backend at that commit writes them token for token,
except that OpenNLP replaced the method-handle lookups of its routine tables
with method references. OpenNLP's `SnowballProgram` and `Among` are Snowball's
Java runtime of that commit, changed the same way and reformatted.

Snowball and its generated code are under the BSD 3-clause license in
`COPYING` (copied from that commit).

## Why the compiler is patched

The Rust backend writes code for a UTF-8 `String`, where a step of one
character moves over a whole code point and lengths count code points or
bytes. The Java backend writes code for UTF-16 `char`s. The two disagree for a
word with a character outside the Basic Multilingual Plane, which is one
character to Rust and two to Java: `hop 3` and the regions it marks stop in
different places, and so can the stem. `rust-utf16.patch` makes the Rust
backend generate the same program over UTF-16 code units:

- The compiler runs the Rust backend with the wide-character encoding the Java
  backend uses, so groupings, suffix tables (and their sort order) and lengths
  are in UTF-16 code units, as in Java.
- String literals become `u16s!("...")`, which the crate turns into a
  `&'static [u16]` at compile time, string variables `Vec<u16>`, and `len` and
  `lenof` count units.
- The quick test before a suffix table lookup reads a code unit, not a byte.
- `slice_to` (`-> s`) does not fail on an empty slice, as Java's does not.
  The two stemmers that use it (Danish and Finnish) only take a slice of one
  consonant, so it is never empty.
- The code imports the runtime of this crate (`src/snowball/runtime.rs`, a
  port of the Java `SnowballProgram` and `Among`).

## Regenerating

`generate.sh` clones Snowball (or adds a worktree of a given checkout), checks
out the commit, applies the patch, builds the compiler, generates the 21
languages of `SnowballStemmer.ALGORITHM` and formats them with the workspace's
`rustfmt.toml`. It needs git, a C compiler, make and rustfmt.

```sh
analysis/stem/snowball/generate.sh [<snowball checkout>]
```
